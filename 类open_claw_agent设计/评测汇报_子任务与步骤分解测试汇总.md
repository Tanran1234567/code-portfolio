## 一、汇报摘要（30 秒版）

本次测试覆盖 Agent 流水线的 **两个层级**：

| 层级 | 测什么 | 数据规模 | 完成情况 | 结论 |
|------|--------|----------|----------|------|
| **Layer 1 子任务分解** | 用户 query → 多个独立子 query | 5000 条 | ✅ **已完成** | **表现优秀**，决策准确率 99.94%，接近可上线 |
| **Layer 2 步骤分解** | 单个子任务 → 多步执行计划 | 5000 条 | ⚠️ **步骤生成 4449/5000（89%）**；**LLM 评判 4449/4449 ✅** | **LLM 评判正确率 68.1%**；complex/branch **92%+**，autonomy **36.7%** |

**核心结论：**

- **用户真实 query 的第一道关卡（Orchestrator 顶层拆分）已经做得不错**，这是你最终目标中最关键的一层。
- **步骤分解不应再用 step_count（3.9%）衡量能力**。改用 LLM 评判后，全量 **68.1% 判为正确（score≥4）**，complex/branch 达 **92%–96%**，说明 **检索/分支类规划基本可用**。
- **autonomy 类（代码排查、策略执行等）是主要短板**，LLM 评判仅 **36.7%**，因模型常出 3 步粗计划，遗漏 gold 中的「复现验证、回归测试、结论输出」等闭环步骤。
- 测试集 gold 本身也是 LLM 生成，应作 **回归参考 / 能力清单**，不宜作逐字真理。

### 3.4 关于「subquery_exact_match 只有 4%」

**不代表只拆对了 4%。** 原因是：

- 模型会去掉「麻烦」「请」等口语词，改标点，轻微改写子 query；
- 标注与预测 **语义一致、边界一致**，但字面不同；
- **应看 similarity（0.866）和 similarity≥0.85（应拆样本约 96%）**，而非 exact match。

**示例（典型成功 case）：**

- 标注：`麻烦查询北京今天的天气，并根据天气给出穿衣建议`
- 预测：`查询北京今天的天气，并根据天气给出穿衣建议。`
- 结果：decision ✅ count ✅ similarity **0.95** exact ❌

### 4.3 具体样例分析：ORCH-STEP-00001

**子任务：** 找出即时零售领域 3 个代表性公司，查门店数量，按该指标从高到低排序。

**测试集标准（5 步）：**

1. 确定 3 个公司候选，记录选择依据  
2. 分别查询每个公司的门店数量  
3. 清洗并统一指标口径、单位和时间  
4. 按门店数量排序  
5. 输出排序表，标注数据来源和不可比项  

**模型输出（3 步，complex-query-decompose）：**

1. `[retrieve]` 找出 3 个代表性公司  
2. `[retrieve]` 查询 3 家公司门店数量（依赖 s1）  
3. `[synthesize]` 按门店数量排序并输出结果（依赖 s2）  

**评价：**

| 维度 | 判断 |
|------|------|
| 主流程方向 | ✅ 正确（选公司→查数据→排序） |
| 依赖链 | ✅ 正确（线性 s1→s2→s3） |
| 可执行性 | ✅ 符合当前 retrieve/synthesize 执行器 |
| 与 gold 步数 | ❌ 3 vs 5 |
| 缺失的中间环节 | ⚠️ 未单独拆「归一化口径」「标注来源」 |

**结论：** 模型步骤 **粗但可用**；测试集 gold **细但偏工程流水线**。低分反映 **schema/粒度不一致**，不是完全不会做。

### 4.4 autonomy 样本特点

- Prompt `autonomy-query-plan` 输出 `items[]`（tool + query），**无 depends_on**；
- 标注期望 6–7 步，含「迭代检查」「最终复核」等闭环；
- 模型常出 3–4 步，方向大致对（调研/排查的主线），但 **步数、依赖、schema 均不对齐**；
- `has_synthesize_rate = 0%` 是预期现象（autonomy prompt 不使用 synthesize action）。

**汇报口径：**

- Layer 2 **整体可用性被旧 step_count 指标严重低估**（3.9% → LLM 评判 68.1%）。
- **complex/branch 可视为接近可用**；上线前重点优化 **autonomy / code_debug / strategy_execution** 类 prompt。
- 建议对外 Layer 2 主 KPI 改为 **judge_accuracy（LLM 评判正确率）**，分 query_level 汇报。
