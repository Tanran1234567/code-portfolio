# Creatinine Ward v3 交接总览


本交接的主结果是：**冻住 v2 世界模型 + v3 肌酐标签 + 线性 logistic 探针**，预测当前 R0 患者未来 48 小时是否新发 SCr-AKI。测试集 AUROC 约 **0.70**。不要把后续 LightGBM / 结构化拼接 / v4 AKI-aware 当作主结果。

## 1. 和 Clin-JEPA 原论文的关系（请对照原文）

本仓库实现的是论文：

> **Clin-JEPA: A Multi-Phase Co-Training Framework for Joint-Embedding Predictive Pretraining on EHR Patient Trajectories**  
> 仓库说明见 `code/README.md`。论文当时双盲评审，仓库里没有作者名单。

思想来源：

- **V-JEPA / V-JEPA 2**（Assran 等，Meta）：在表征空间预测未来，而不是重建像素/文本。Clin-JEPA 把这套搬到 EHR 轨迹。
- **V-JEPA 2-AC**：动作条件（action-conditioned）预测器。本实验的 AC Transformer 对应论文 §3 的 predictor。
- 论文架构速查：`code/docs/architecture.md`（§3 模型、§4 训练）
- 论文训练五阶段：`code/docs/training.md`
- 论文下游评测（ICU 上是 **MLP probe**）：`code/docs/evaluation.md` §5.4

### 1.1 对齐的部分

| 模块 | 论文 | 本实验 | 代码 |
|------|------|--------|------|
| 编码器 | Qwen3-8B + LoRA，取 **last-token** 隐状态 → 4096 维 | 相同 | `code/clin_jepa/training/encoder_ops.py` |
| Predictor | 6 层 pre-norm Transformer，隐空间 4096，约 92M | 相同骨架 | `code/clin_jepa/model/predictor.py` |
| 训练目标 | JEPA：预测未来 **表征**，L1，EMA target encoder | 相同 | `code/clin_jepa/training/` |
| 推理 rollout | 用已记录的未来 action 做条件预测 | 相同（不是无干预预报） | `code/clin_jepa/evaluation/rollout.py` |
| 轨迹 shard 字段 | `per_hour` / `windows` / state·action·static 文本 | 医院线刻意做成同一 schema | `code/clin_jepa/data_hosp/step06_hosp_trajectories.py` 文件头说明 |

### 1.2 我们相对论文 **新加 / 改掉** 的部分

| 点 | 论文（ICU） | 本实验（病房 Creatinine Ward） |
|----|-------------|-------------------------------|
| 人群 | ICU stay | **无 ICU** 住院，见第 2 节 |
| 时间粒度 | ICU 更密的节点（论文设定） | **固定 24h 桶**，原点 `admittime` |
| 时间编码 | 离散步位置编码为主 | 额外 **绝对时间加性编码**（见第 5 节） |
| 动作对齐 | 需对照论文实现 | v2 起改为 `target_interval`：预测 \(z_{t+1}\) 配的是目标日 \(u_{t+1}\) |
| 下游分类器 | 论文 §5.4 是 **MLP**（4096→512→1） | 主结果是 **线性 logistic**，不是 MLP |
| 下游怎么用向量 | 通常在单步 \(z\) 上 probe | 把 **72h 内 3 个 state / 3 个 action 向量先平均再拼接**（见第 7 节） |
| 标签 | ICareFM 等 ICU 任务 | **KDIGO 风格血清肌酐 AKI 发生** |

对照论文时请记住：架构同源，任务、时间尺度、探针协议都不是论文主表那一套。

## 3. 当前 v3 模型架构（从头到尾一条链）

```text
MIMIC-IV 原始表
    │  step01–07（v1 预处理，24h 分桶 + 白名单文本）
    ▼
data/v3_processed/trajectories/*.pt     每个 24h 桶三句英文（v3 已改肌酐句 + 挂上 AKI 标签）
    │  冻住的 v2 编码器（Qwen3-8B LoRA）  ← 权重不在本包，在 GPU 盘
    ▼
每个节点：z_state, z_action, z_static ∈ R^4096   （last-token）
    │  冻住的 v2 AC Transformer predictor
    ▼
可选：用已发生的未来 action 滚出 ẑ_{t+1}, ẑ_{t+2}
    │  线性 logistic 探针（本交接的主结果）
    ▼
未来 48h 是否新发 SCr-AKI（当前必须是 R0）
```

组件职责：

| 组件 | 输入 | 输出 | 本包位置 |
|------|------|------|----------|
| 文本编码器 | 人口学 / 当天 state 文本 / 当天 action 文本 | 各 4096 维 | `code/clin_jepa/training/encoder_ops.py` |
| Predictor | 历史 \(z\)、static、**记录的** 未来 action、绝对时间 | \(\hat z_{t+1}\) | `code/clin_jepa/model/predictor.py` |
| EMA target | 训练时才有 | JEPA 损失的停梯度锚 | 推理丢弃 |
| 线性探针 | 72h 平均后的拼接向量 | 二分类概率 | `code/clin_jepa/evaluation/creatinine_aki_v3_probe.py` |

v1 只验证「文本里已写的肌酐三分类能不能被探针读出来」（操作阈值 1.5，**不是 AKI**）。  
v2 重训 predictor，改动作对齐。  
**v3 才进入临床主任务：KDIGO 风格新发 AKI。** 编码器/predictor 仍用 v2 的冻住权重。

### 4.1 24h 分桶（相对论文的关键改动）

- 时间原点：本次住院 **`admittime`**
- 第 0 桶：`[admittime, admittime+24h)`，节点时刻记在桶 **结束**（24, 48, 72, … 小时）
- 只用完整日；最后不满 24h 丢掉
- 配置：`code/configs/data_hosp/creatinine_ward_features_v1.yaml` 里 `temporal.step_size_hours: 24`，`max_steps: 30`，`complete_bins_only: true`
- 一人一条完整轨迹（`stride` 很大），不滑窗复制样本

桶内聚合：白名单化验默认取当天 **最后一次**（`within_bin_agg: last`）。  
**v3 只把肌酐改成「桶内全部原始值写入文本」**，其它化验仍是 last。标签不从 last 值猜，而从全部原始肌酐算。

## 5. 绝对时间编码（相对论文的实现细节）

论文 ICU 节点更密，位置编码往往够用。病房 24h 桶、住院可长到 30 天，我们给 predictor 加了 **加性绝对时间**：

配置（v2，v3 探针沿用这个 predictor）：

`code/configs/train/pretrain_creatinine_ward_v2_action_aligned.yaml`

```text
predictor:
  prediction_mode: residual          # 预测残差，初始化成恒等
  action_alignment: target_interval  # (z_t, u_{t+1}) → z_{t+1}
  use_continuous_time: false
  absolute_time_additive: true
```

实现：`code/clin_jepa/model/predictor.py`

- 把 `time_hours` 换成「天」：\(t_{day}=t_{hour}/24\)
- 9 维特征：\(\log(1+t_{day})\) 以及频率 \(\{1,2,4,8\}\) 的 sin/cos
- 两层 MLP 投到 **4096 维**，**加到** \(z_{state}\) 和 \(z_{action}\) 上（不是拼进去）
- 最后一层初始化为 0，训练开始时等价于「还没有时间调制」

文本里已经去掉机器时间前缀（`include_machine_context: false`），时间只走这条向量通道，避免模型走捷径读字符串里的小时数。

v2 相对 v1 的另一处修正：动作对齐从「当天 u_t」改为「目标日 u_{t+1}」。说明：`code/BITAHUB_CREATININE_WARD_V2_RETRAIN.md`。

## 6. 肌酐基线、R0/R1/R2，以及下游任务定义

完整临床口径写在：`reports/creatinine_ward_v3线性探针_主任务A汇报_20260908.md`。这里只留交接用的短版。

**基线（Reference A）**  
优先：该患者其他住院、入院前 7–365 天肌酐的 **中位数**。  
否则：本次住院第一次肌酐，并标记 fallback。

**单次化验分期（仅 SCr，无尿量；2 期和 3 期合并为 R2）**

- \(C/B \ge 3\) 或 \(\ge 2\) → **R2**
- \(C/B \ge 1.5\) 或 48h 内绝对升高 ≥0.3 mg/dL → **R1**
- 否则 **R0**
- 同刻冲突 / 无基线 / 窗内无肌酐 / 随访不足 → **RU**

节点标签取窗口内最高分期。未来 48h = 当前桶结束后的 48 小时。

**主任务 A** `future_48h_scr_aki_occurrence`：

- `anchor_idx ≥ 2`（已有 72h 历史）
- 当前必须 **R0**
- 排除未来 48h 为 RU
- y=1：未来最高为 R1 或 R2；y=0：未来可判定且一直 R0

测试集约 4032 锚点、488 个正类（12.1%）。不要用「当前分期不限」的混合题 AUROC 0.75 当主数字。

## 7. 下游分类器：线性探针（不是论文里的 MLP）

代码：`code/clin_jepa/evaluation/creatinine_aki_v3_probe.py`  
配置：`code/configs/eval/creatinine_aki_v3_probe.yaml`

### 7.1 用了哪些向量、哪些被平均

每个 24h 节点经编码器得到三个 4096 维向量（与论文相同：文本 last-token）：

- \(z^{state}_t\)：当天状态文本  
- \(z^{action}_t\)：当天干预文本  
- \(z^{static}\)：整段住院人口学（每人一份，不随 t 变）

主任务在锚点 \(t\)（`anchor_idx`）上构造：

```text
history = mean( z_state[t-2], z_state[t-1], z_state[t] )
          ‖ mean( z_action[t-2], z_action[t-1], z_action[t] )
          ‖ z_static
        = 4096 + 4096 + 4096 = 12288 维

full48  = history ‖ mean( ẑ_{t+1}, ẑ_{t+2} )
        = 16384 维
```

要点：

- **平均发生在探针侧**，JEPA 训练时并没有对 3 天做这个 pooling。  
- 论文下游 MLP 多半接 **单步** 4096 维 \(z\)；我们是 72h mean-pool 后再线性分。这是有意的任务适配，不是论文主表复现。  
- `full48` 的未来 action 是病历里 **已经发生** 的目标日干预（条件 rollout）。  
- 代码对应：`build_examples()` 里 `.mean(dim=0)`。

### 7.2 线性探针怎么训

- `StandardScaler` + `LogisticRegression`，`class_weight=balanced`
- \(C \in \{10^{-4},10^{-3},0.01,0.1,1\}\)，在 **val 的 macro-F1** 上选 C
- 同一患者多个锚点时权重按患者均分
- 主指标：AUROC、AUPRC（无信息 AUPRC ≈ 12.1%）
- 置信区间：患者级 bootstrap 200 次

**不是** LightGBM，**不是** 论文 `code/clin_jepa/evaluation/probes.py` 里的 `MLPProbe`（4096→512→1）。

### 7.3 主结果（测试集）

| 特征 | AUROC | 95% CI | AUPRC |
|------|------:|--------|------:|
| history | 0.705 | 0.67–0.74 | 0.252 |
| full48 | 0.713 | 0.68–0.75 | 0.259 |

history 与 full48 区间重叠，**不能说 rollout 有可置信增益**。  
数字来自 BitaHub `aki_v3_probe/results.json`（embedding/checkpoint 未打进本包）。

## 9. 可按这 8 句讲

1. 从 MIMIC 无 ICU、完整 24h、有肌酐的住院里，按配额抽出冻住的 3000 人。  
2. step01–07 把住院切成 24h 桶，白名单化验和用药写成英文，Qwen 编成 4096 维。  
3. 相对论文：我们用日桶，并给 predictor 加了绝对时间编码。  
4. v3 用既往 7–365 天中位肌酐（否则入院首次）做基线，按倍数和 0.3 规则打 R0/R1/R2。  
5. 主任务是当前 R0、未来 48h 是否新发，不是「任意当前状态未来还是不是 AKI」。  
6. 下游是 **线性 logistic**，把过去 3 天的 state/action 向量平均后拼上 static。  
7. 测试 AUROC 约 0.70；predictor 再滚 48h 没有可置信增益。  
8. 这不是完整 KDIGO 诊断：无尿量，2/3 期合并，队列也不是自然患病率。
